### Fixed
- **Hook timeouts in `.claude/settings.json.template` are now seconds, and attestation can see the unit**: Claude Code reads a hook's `timeout` in seconds and caps it at 600 s; the template wrote milliseconds (1000-10000), so every hook timeout on a fresh install was effectively disabled while `doctor.sh --attest` reported COMPLIANT, because it compared the install against the same template. Every template value is now a per-hook second budget chosen from a healthy-host measurement of each hook (90-500 ms for all but `caddy.sh` at 1.7 s) with startup headroom: 5 s for the light hooks, 10 s for `caddy.sh`, 8 s for the interlock legs and `sessionend-flush.mjs` (inner worker 5000 ms), 10 s for `precompact-flush.mjs` (inner worker 6000 ms). `doctor.sh --attest` gains a bound that does not derive from the template: a hook timeout outside 1-120 s, in the template or in the install, is NONCOMPLIANT, so a template cannot certify its own unit mistake and a millisecond-era install cannot pass against a corrected template merely by exceeding it. The installer regression suite proves fresh (copy) and reinstall (merge) paths both render the second values and leave an operator-owned hook untouched. Internal daemon `*_MS` budgets are unchanged. **This does not close issue #104: automated input acceptance remains NOT PASSED.**
- **fleet-delivery mod 0.3.0: a seat's refresh lifecycle can no longer clear over a submit that has not started (issue #105)**: before every submit the mod publishes an admission ticket at `<roomRoot>/state/admit/<seat>/<file>.<attemptNonce>.json` carrying this process's pid, and releases it only when that submit's own promise settles or the owning process is dead (`ESRCH`); time, ledger status, `/delivery-reconcile` and item sweeps never release it (Contract E). A process that cannot name its own pid writes no ticket and submits nothing, recorded once as `deferred:admission-no-pid` (Contract F). The supervisor's per-seat hold file `<roomRoot>/state/holds/<seat>.json` freezes ordinary delivery as `deferred:supervisor-hold` for the whole capsule, clear and resume window, with the supervisor's own request lines still passing; a stale or unreadable hold file holds everything. A ticket that cannot be written defers as `deferred:admission-unwritable` with a bounded retry only for a confirmed non-publication. Tickets with no valid owner pid (legacy null-pid admissions, damaged owner fields) are retained, said once per file per module load in the transcript, and left to the operator; the companion supervisor (agent-room PR #16) waits on live tickets before each lifecycle leg and names unowned ones in its alert. Tests: `plugins/fleet-delivery/tests/supervisor-hold.test.mjs` (Node 24) and `plugins/fleet-delivery/hooks/fleet-delivery.test.ts`.
- **Two vectors could not run on Linux, from a Windows-only path idiom in the test fixture (issue #104, CI arbitration)**: **automated input acceptance remains NOT PASSED.** `#104 G12` and `G27` failed on ubuntu while passing 30/30 on Windows, because the module suite derived the hook's path with `new URL(import.meta.url).pathname.slice(1)`. A file URL's pathname carries a leading slash on both platforms, so the slice yields `C:/dev/...` on win32 -- **absolute** -- and `home/runner/...` on POSIX -- **relative** -- after which `path.resolve` prefixed the working directory and produced a doubled root. **The production code never had this**: both interlock files already used `fileURLToPath`, which is correct on both, and the wiring resolution takes absolute inputs throughout. Established before fixing, because the two failing vectors were the newest and the most load-bearing and a shared defect would have been far more serious. **The path class was also ruled out for `comparablePath` on POSIX**, since our whole N1/F-D line of work was about path spellings: the drive-fold requires a single-character first segment, so it is a no-op on ordinary POSIX paths and matching is unaffected. One cosmetic consequence is named rather than left implicit -- a POSIX root whose first segment is a single letter (`/x/...`) folds to `x:/...`, which is applied to both sides and so still matches, and the two spellings it makes equal cannot coexist on one host. **Two more latent Linux failures were found by looking rather than by waiting for CI**, both in vectors added in earlier legs: an assertion that the fixture carried the MSYS spelling used a literal `/"\/[a-z]\//` regex, which cannot match a POSIX path; and a `slice(3)` meant to drop `C:/` silently mangled `/home/...` into `me/...`, so the assertions around it would have passed or failed for the wrong reasons. The path-spelling vectors now use **fixed synthetic roots** -- one win32-shaped, one POSIX-shaped -- so the matcher is tested as the pure string logic it is, each platform exercises the other's root shape, and the root is stripped with a platform-correct rule instead of a character count. **Verified on real Linux, not by reasoning:** a `node:24` container reproduces the pre-fix failure as exactly `not ok 12` and `not ok 29` and nothing else, and the fixed tree runs 30/30 on the module suite and 315 tests with 0 failures on the runner suite (3 platform-guarded skips, all pre-existing). - **The interlock gains a deliberate manual-only recovery, and four reproduced fail-opens are closed (issue #104, following the independent review of `89ad6c5`)**: **automated input acceptance remains NOT PASSED.** **No permanent tool outage.** The states in which the armed interlock denies a tool call were enumerated by *reaching* each one against the shipped hook rather than reasoned about: eight of ten deny, and **five had no recovery at all** (a gate whose timestamp is not a number, a clock behind the gate stamp, a directory at the gate path, and a gate or state the filesystem will not let anyone write). Two manual paths now cover them, and each covers what the other cannot. **Stopping the managed runner** makes the hook inert, because a proof whose `runner_pid` is no longer alive means there is no automatic writer and so the denial has no subject -- and it is the only recovery that needs **no write at all**, which is what makes it the answer to a read-only filesystem. **The manual release** is the guaranteed path: a human writes `interlock-release.json` into the session's interlock directory, most easily through the new `--release <session-id> "<reason>"` subcommand, which requires both arguments, defaults neither, and refuses to write into the wrong install rather than reporting a success that released some other seat. After a release the hook stops denying and stops marking, expresses **no permission opinion** (the call goes to the host's own check and a human answers the dialog), and the runner refuses **every** automatic write by name for the rest of the binding -- **latched**, so deleting the file does not re-enable automation; only a new session does. That is not the silent fallback that was refused: the protection is not disabled, it is made unnecessary, because the hazard is an automatic keystroke and after a release there are none. Every near-miss (a bare `touch`, a blank reason, another seat's file) keeps denying and **says which way it was wrong**, and both sides write the operator's own reason to the daemon log. **And one state was permanent in the worst way**: a wiped interlock directory left the runner holding automatic writes for ever (safe) while the hook went inert for want of a proof (unprotected), with nothing to restore it. The runner now re-arms with a fresh nonce -- the one automatic transition in the unit, and it runs toward *more* protection. **Exclusion could be lost, which is the opposite direction from an outage and needed its own enumeration.** A gate was stolen on **age alone** from a holder whose process was alive and whose nonce matched; the claim that a legitimate holder could not reach that age was false for both held spans and false unconditionally on a forward wall-clock step. Reproduced end to end with no injected errors and a +6 s step: the Enter went out with a live permission check recorded. The fix is **detection, not prevention** -- the steal is the gate's only recovery from a recycled pid, and no age bound survives a clock step -- so both held-gate paths now re-verify **on-disk token ownership**, `commitClearSubmission` does the same instead of trusting an in-memory handle, the pending re-read happens on both paths rather than being skipped on the held one, and `releaseGate`'s boolean (the one "I lost ownership" signal there is) is propagated and named. Three more ways the gate could be taken from a live holder are closed: a **transient read error** on the gate file read as "no holder" (one `EMFILE` on a 150-process host stole a live gate -- this document's own substitution, *cannot see therefore nothing there*, applied to the gate instead of the transcript); a gate **created but not yet stamped** -- the ordinary state of one just taken -- read as free, and is now stealable only on the file's own mtime; and a **release deleted another holder's gate**, because only the `held` kind was protected against a foreign token. **An unreadable `state.json` was treated as an empty one**, so one `EBUSY` during another call's `PreToolUse` destroyed a live marker **with its dialog on screen**, reset the counters, and left all four evidence legs passing and the runner reading ready; the invented state also carried a null write stamp, so the same invocation skipped the drain. `readState` already distinguished missing from unreadable and the hook now honours it: only *missing* is initialised, unreadable denies, and a clearing event that cannot read refuses to clobber. The vector that previously **blessed** this is rewritten with a live marker to lose. **Leg 4's deficit was permanent for the session**, so one dropped `pre_runs` increment refused the capsule request and the clear for ever -- a permanent automation outage recoverable only by restart. Every `PreToolUse` now counts as an invocation including the ones that deny, and a remaining shortfall is forgiven **on positive evidence that the hook is alive**, never on a timer, and logged when it is. **Leg 3 no longer accepts a `Stop` alone**: that proves the file runs, not that `PreToolUse` is wired, and combined with a memoised wiring check it would have let both mechanisms be blind at once -- so `pre_runs >= 1` is required unless the reader has provably seen no tool calls at all. The **wiring leg is no longer memoised on success** (it is keyed on the settings files' mtime and size, because `/hooks` can rewrite them mid-session), must name **this** runner's sibling hook, and must find all three events in **one** file. **Two silent allows in the hook are closed**: an unreadable payload or a renamed `session_id` used to exit 0 with no marker, so the event name now rides as an argv in all three template entries and a `PreToolUse` that cannot name its session denies. **On the drain, the claim is reduced to what it can support.** Measured against node-pty 1.1.0, `write` returns `void` and discards the socket's backpressure boolean, and there is no "input consumed" event -- so `pty.write` returning proves nothing about consumption and **no supported mechanism can**. What the drain buys is a bounded quiet period: no permission check may *start* for 120 ms after the last stamped write. The residual needs the child to be more than 120 ms behind on reading stdin, which is unobservable from here and unbounded in principle, and it is now named as an **undischarged proof obligation** rather than described as covering the gap. Three documentation corrections went with it: the write stamp applied to four of seven automatic writes, not all (the `/clear` **text** write was a real gap and now stamps; the two `Ctrl-U` kill-lines deliberately do not, because `Ctrl-U` cannot answer the dialog); the "no interval" guarantee is about the **marker** ordering and not the **byte** ordering, and the two are now stated separately; and a **forward** clock step skips the drain entirely, which one wall clock cannot distinguish from elapsed time (the backward case drains in full). Requiring the child's output generation to change instead of a timer was considered and declined with reasons -- the runner cannot block on its own output pump, and output generation is evidence of *some* output rather than of *this* byte. Also: settled markers are now really **deleted** under the gate rather than only discounted on read, and the runner's `interlock-pending-overflow` branch was unreachable (`> PENDING_MAX` against a hook that denies at `>=`) and now is not. Two vectors that **claimed a recovery they did not exercise** are rewritten: both advanced the hook's counter without advancing the reader's, a shape no real seat produces. Verified by `#104 I11`-`I19` and `G18`-`G25`; every finding was reproduced against the pre-fix tree before being fixed and re-confirmed afterwards. - **A bounded pre-permission interlock now stands between every automatic keystroke and the permission dialog (issue #104, following #110)**: **automated input acceptance remains NOT PASSED** -- what changed is which window is open and how wide it is. #110 gated every automatic write on the bound transcript holding a `tool_use` with no matching `tool_result`. Measured on binary 2.1.310 that signal is **not reliably on disk while the dialog is on screen**: on 1 of 4 real-dialog observations the record occupied bytes 286521-288638 while the file was 283263 bytes at all three samples taken during the dialog -- not partially written, not flushed at all -- and readiness answered `ready: true` with a live permission prompt up. The flush carrying both the call and its answer arrived only after the cancellation, a creation-to-readability lag of **≥ 2.44 s**. The host's transcript writes are buffered and the flush is unannounced, so no amount of care in a reader produces a signal that is not there. The evidence now comes from somewhere **causal** instead: `daemons/pre-permission-interlock.mjs` is a new `PreToolUse` / `PostToolUse` / `Stop` hook that the host runs synchronously **before** the permission check, and the runner and that hook take **the same gate** around their respective critical sections. Both mechanisms apply at every gated boundary and readiness requires both. **It is a mutex, not a second file to poll**: a check followed by a write is not exclusion, so the runner's "is a permission check in flight" read and its `pty.write` happen inside the same critical section the hook must enter to record one. Either the hook's marker is on disk and `fsync`ed before the runner's read, or the runner's write has already returned before the hook can acquire -- and in that second case the hook waits out `INTERLOCK_DRAIN_MS` (120 ms) for bytes still travelling to the child before it lets the check proceed, because `pty.write()` returning is not the child having consumed the byte. The clear's prepare-to-commit span -- #110's residual (3), left open because the only refusal available there is terminal -- is closed by **holding** the gate across it rather than by re-testing at commit. **Keying readiness on a marker is only sound if the runner can prove the hook is live for the bound session**, which is why #110 declined this route; that proof is four legs, all required, each with its own refusal: the `proof.json` nonce, session id and runner pid match the binding in memory (`interlock-proof-missing` / `-unreadable` / `-mismatch`); the hook file is still the one the proof was written about, by sha256 (`interlock-hook-missing` / `interlock-hook-changed`); the **host** has actually invoked the hook for this nonce (`interlock-hook-not-observed` -- `Stop` fires at the end of every turn, so a session with no tool calls can still satisfy it); and the hook has not **stopped** running, detected positively by comparing its invocation count against the transcript reader's `tool_use` count as a delta since the last point both agreed (`interlock-hook-missed-tool-calls`). Plus `interlock-hook-not-wired` if the hook is absent from `PreToolUse`, `PostToolUse` or `Stop` with an all-tools matcher in a settings file the runner can read. **Missing, stale or failed evidence means automatic input stays held, and never reads as "no tool call is pending"** -- including `AIGENT_INTERLOCK=off`, which silences the hook *and* makes the runner refuse (`interlock-disabled`), so the switch cannot create a fail-open in either direction. Staleness is deliberately **not** idle-time based: a quiet session makes no tool calls, so an idle rule would hold automation on a healthy seat. - **Declared lifecycle extension (issue #49)**: an install supervised by an outside process can now attach that process's own completion handshake to the two lifecycle verbs by declaring it in `<target>/.aigent/lifecycle-extension.json` (`{"schema": "LifecycleExtension/v1", "resume_ack": "...", "capsule_ack": "..."}`), instead of forking `skills/resume/SKILL.md` or `skills/context-capsule/SKILL.md`. Both fields are optional; each is a single line, free of control characters, and may use `{capsule_id}` at most once. The declaration is data, never code: nothing loads a module, spawns a process, or teaches core any particular supervisor's vocabulary, so the same seam carries any protocol without core knowing one of them by name. `.aigent/` sits outside every installer-managed tree, so the declaration survives an install and an update with no preservation entry of its own. The store was one file per plugin per Claude config directory and last-writer-wins, so two seats sharing a config directory could erase each other's ledger; the log is one file per seat under that seat's memory root. A finished import, or a first clean read that finds nothing to import, writes a `store-import` marker line to the log, and a log carrying it never reads the store again; the README says how to repair or remove an unreadable store file safely. Every log write goes to a temp file renamed over the log, so a crash never leaves a cut-off log. A change is on disk before the mod acts on it: a claim that cannot be written is undone and retried on the next tick, never submitted, and a reconcile that cannot be written changes nothing. After a hot reload only the newest module writes. When an append would take the log near the engine's read cap, the mod rewrites it with one line per id and drops Room ids whose inbox file is gone, but nothing when the inbox folder itself is missing; job ids and Room ids still in the inbox stay. Each layer was synthetic-tested before the next layered on. The 1-2-cycle gate was overridden in this release on principal authority; future releases return to the gate.

### v0.4.1: Rhythm

- `vault/memory/BODY_STATE.json` schema extended with `last_capsule` field
- `.claude/commands/open.md` Step 2.5: capsule resume offering
- `.claude/commands/close.md` Step 0.5: auto-integrations (skip-digest if 0 staged, auto-create capsule, demote prior active capsule)
- `skills/context-capsule/SKILL.md`: capsule lifecycle (active → resumed → resolved) + parent_capsule_id chain
- `skills/caddy-mute/SKILL.md`: new skill, 5 classes (memory/context/body/routing/all), 4h default expiry
- `daemons/caddy.sh`: class-mute helper (Git-Bash → Windows path translation), 5 existing hints class-tagged, 3 new hints (memory/context/body)
- `vault/memory/CADDY_MUTES.json`: schema initialized

### v0.4.2: Input (auto-capture)

- `daemons/memory-capture.sh`: high-confidence trigger phrases auto-stage candidates to MEMORY_CANDIDATES
- 50-row hard cap, 24h dedupe window, append-only
- 7 trigger patterns: `remember that X`, `remember to X`, `from now on X`, `new rule: X`, `rule: X` (tightened to require sentence boundary), `we decided/agreed X`, `going forward X`
- Best-effort: capture script failure does NOT block Caddy hint output

### v0.4.3: Reflection (smoke test)

- `skills/system-check/SKILL.md` + `daemons/system-check.sh`
- Audits: 8 wired skills, 8 daemons (parse), 7 state files (valid + fresh), capsule frontmatter sanity, mirror discipline (vault ↔ public), daemon error log surfacing
- Reports: green/red per path, exits 0 if all PASS

### v0.4.4: Hestia wiring

- `skills/sweep-now/SKILL.md`: dispatches Hestia sub-agent for 3 vault sweeps (DELEGATION_TRACKER stale items, HEAT_INDEX dormant flips, broken wikilinks), appends entry to HESTIA_SWEEP_LOG
- `skills/body-check/SKILL.md`: reads HESTIA_SWEEP_LOG mtime → `hestia_last_sweep` field; null OR >7d → `recommended_reflex: sweep`
- `vault/memory/HESTIA_SWEEP_LOG.md` template: initialized empty

### v0.4.5: Capsule chain compaction

- `daemons/capsule-compact.py` + `skills/capsule-compact/SKILL.md`
- When parent_capsule_id chain >= 5, summarize oldest 3 into a chain-summary capsule
- Compacted capsules stay on disk with `compacted_into:` marker for archeology
- Idempotent: re-running on already-compacted chain is a no-op

### v0.5.0: Agent fitness (the big one)

- `daemons/agent-fitness-extract.py`: scans Claude Code JSONL transcripts for `Agent` tool dispatches, classifies outcome (clean/blocked/errored/partial) via heuristic, appends rows to AGENT_FITNESS.md
- `skills/agent-fitness/SKILL.md`: surfaces calibration ratios per sub-agent
- `vault/memory/AGENT_FITNESS.md` template: initialized with schema header
- Dedup by (session_id, tool_use_id): idempotent extract

### Doctrine banked alongside

- `vault/concepts/Somatic Layer.md`: base doctrine
- `vault/concepts/Somatic Roadmap.md`: version queue + ship history
- `vault/concepts/Somatic v0.4.1 Wiring.md` through `vault/concepts/Somatic v0.5.0 Agent Fitness.md`: 6 spec docs
- "Silent successes hide failures" doctrine: `2>/dev/null` and `exit 0 on no-op` are anti-patterns; vault daemons log to `<vault>/memory/.daemon-errors.log`
- Doubled-write rule: every skill/daemon change writes to BOTH local `.claude/skills/` AND public `skills/`. Prevents v0.4 wiring gap recurrence.

### Bugs found and fixed in this release

- v0.4.1 Caddy class-mute Python heredoc was passing Git-Bash `/c/...` paths that Python on Windows native could not open; mute file silently failed to load → mute system never worked. Fixed with path translation at top of heredoc.
- v0.5.0 dedup was extracting truncated session/tool_use IDs from the ledger but checking against full IDs → re-runs would duplicate rows. Fixed by storing full IDs in ledger.
- v0.4.2 `rule:` regex was matching mid-sentence ("what's the rule for X") as doctrine. Tightened to require sentence boundary + colon + space.
- v0.5.0 outcome classifier missed real blocked patterns ("BLOCKED:", "are denied", "blocker-found"). Added 11 keywords.

## [0.2.2] (2026-04-27): "Measurement primitives + adversarial doctrine"

Foundation for the v0.3 measurement release. Six original inventions ship as
doctrine + skills + scaffolds. None of them depend on v0.3 measurement skills
to be useful immediately; together they establish the data substrates that
v0.3 will build on.

### Added

**Adversarial doctrine (principal-side discipline):**
- `vault/concepts/Reading Agent Output Defensively.md`: companion to `/honesty-check`. Tells the principal how to spot when an agent didn't volunteer the truth. 10 patterns of confident-sounding bullshit + the standard push-back move.

**Cost of Confidence (longitudinal trust calibration):**
- `vault/concepts/Cost of Confidence.md`: names the pattern: every confident claim that turns out wrong is a trust-decay event.
- `skills/trust-decay/SKILL.md`: two-phase ledger skill. Phase 1 captures confident claims; Phase 2 resolves them as right or wrong. Pairing is the whole point.
- `vault/memory/TRUST_DECAY.md`: the ledger file (Open + Resolved sections; auto-managed).

**Common Failure Modes (institutional debugging memory):**
- `vault/concepts/Common Failure Modes.md`: names the pattern: every confirmed `/diagnose` outcome becomes Phase 1 corpus; recurring patterns graduate to Phase 2 doctrine.
- `vault/memory/FAILURE_MODES.md`: corpus file (Phase 1 entries + pattern frequency tracker).
- `skills/diagnose/SKILL.md`: extended with Step 6: write verified diagnosis outcomes to the corpus.

**Honesty Ledger (structured artifact, not just doctrine):**
- `vault/memory/HONESTY_LEDGER.md`: longitudinal record of `/honesty-check` outputs. Pairs to TRUST_DECAY.md when discrepancies surface.
- `skills/honesty-check/SKILL.md`: extended to also write a structured machine-readable entry per invocation. Resolution field updated by `/trust-decay resolve` later.

**Attention Reconciliation (drift detection at /open):**
- `vault/concepts/Attention Reconciliation.md`: the doctrine. Where you said you'd spend attention vs where you actually did, computed every session.
- `skills/open/SKILL.md`: extended with two new protocol steps:
  - Step 7: decision aging check (surfaces 30/60/90-day decisions awaiting outcome capture)
  - Step 8: attention reconciliation (compares last 7 days of daily notes to ACTIVE_PRIORITIES, flags drift > 20%)

**Promote (conversation → durable artifact):**
- `skills/promote/SKILL.md`: selective elevation skill. Take a slice of the current conversation and produce a vault concept / project / person / decision artifact. Pairs with `/close` (transient) by handling the durable layer.

**Caddy:**
- `.claude/skill-index.json`: added `/promote` and `/trust-decay` entries with rich triggers.

### Changed
- `/honesty-check` skill produces both human-readable summary AND machine-readable ledger entry per invocation.
- `/diagnose` skill writes Phase 1 corpus entries on verified diagnoses.
- `/open` skill protocol now includes decision aging + attention reconciliation steps before main orientation output.

### Authority reasoning
All AL1 (additive doctrine + auto-capture extensions to existing skills + scaffold files). No kernel changes; no breaking changes; all measurement layer is data-collection-only at this release. v0.3 will ship the analyzers (`/retro`, `/skill-economics`, `/quality-pulse`) that consume this data.

### What's NOT in this release (deferred to v0.3)
- `/retro` quarterly analysis skill: needs at least 30 days of TRUST_DECAY + HONESTY_LEDGER + FAILURE_MODES data
- `/skill-economics`: needs Caddy hint-followed tracking (Caddy improvement queued separately)
- `/quality-pulse`: Friday three-question survey skill
- Cadence enforcement hooks (D2 from v0.3 brief)
- `/missed-cadence` skill (D3)
